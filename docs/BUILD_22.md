# Build 22: group calls and chat corrections

Group chats can start voice or video calls with up to eight people, including the caller. The caller chooses members; each recipient explicitly accepts. The immutable invitation roster must consist of current, trusted, unblocked group members. Each pair uses the existing authenticated signaling and WebRTC media connection. Leaving or declining one participant does not terminate the remaining connected pair. The roster is fixed for a call; adding participants during a live call is not included. This device mesh increases bandwidth with each participant; it introduces no central media service.

During an active video call, Share screen invokes the system consent UI. iOS uses a bundled ReplayKit broadcast extension and the existing private app group; Android uses the WebRTC MediaProjection flow. Screen frames travel through the established media connections and are not recorded to files. Microphone audio remains the existing call audio; system/app audio is not captured. Stopping sharing restores the camera while preserving mute/camera choices. Cancelling, hanging up, interrupted capture and late callbacks release the stream and invalidate its short-lived request token. The local broadcast socket has nonblocking writes and permits only one pending bounded JPEG frame.

Chats and Calls use a persistent native list header for search. Native scrolling reveals or conceals it without changing the list viewport. Short and empty lists retain enough travel to reveal it. Focus or a nonempty query keeps search available. The Chats title also opens search accessibly. Scroll indicators stay hidden. The keyboard and attachment grid share one reserved bottom area; the keyboard icon restores typing. The grid contains seven colored actions in two fixed rows, with no scrolling. The composer separator is removed and the recording stop square is red.

Long press opens message actions at the measured message position, with a moving preview and a fading backdrop/actions. Dismissal returns the preview before the native modal is removed. Safe-area bounds keep the menu on screen; long text can scroll within its preview and text is never replaced by an ellipsis. Reduced Motion skips movement. Saved custom emoji appear first in quick reactions, with no empty spacer before the plus.

Only a message author may edit their sent text or delete an individual sent item for everyone. Revisions are authenticated and ordered locally; deletion is terminal, including when it arrives before the original message or its attachment. Photos, voice notes, documents, location, contacts, polls and events use the same deletion control. Deleted content becomes a placeholder and reactions/media are removed from the local database. Clearing a whole conversation never requests remote deletion. Already queued explicit message changes survive a later local clear.

All participants should update to build 22 before group calling, screen sharing, editing or deletion tests. Build 21 does not implement the new group or message-change controls. Deletion cannot revoke a copy someone separately saved or exported.

## Verification

Automated checks cover authenticated three-participant voice/video call setup, host departure, individual decline, unauthorized/duplicate rosters, bounded ring deadlines and durable group invite recovery. Screen tests cover explicit consent dispatch, cancellation during capture, late tracks, remote replacement failure, camera restoration and hangup cleanup. Actual Swift socket code transferred a generated 1 MiB fixture through a delayed local reader without truncation; no real camera or screen was captured.

Database tests cover direct/group edit authorization, out-of-order revisions, deletion before media arrival, all message kinds, local conversation clear and quick emoji ordering. UI tests cover short-list search travel, keyboard/menu inset preservation, long press versus tap, explicit edit/delete actions, native-modal dismissal sequencing and reduced-motion behavior. Browser review uses actual components with fictional contacts/messages at 390 and 320 pixel widths. It does not establish physical iOS keyboard animation or real media connectivity.

Before considering the feature physically accepted, test three updated phones: incoming accept/decline, voice/video both directions, host departure, microphone/camera controls, an OS-approved screen broadcast, return to camera, OS stop/hangup/background interruption, and reconnect. Also test native keyboard/menu transitions, short/empty Chats and Calls search, long-message menus, offline edits/deletion and large accessibility text. Build/signing/distribution results are recorded in BUILD_LOG after completion.
