# Mnelo privacy controls

Defaults are database-enforced: relevant matches only, phone visible to nobody, exact location never public, and requests from relevant matches. `update_privacy` derives the actor from Auth, validates each supported choice and limits changes to 30/hour. Clients cannot write another person's settings or add an exact-location visibility mode.

Discoverability controls stranger search and matching. Everyone means authenticated people, not an anonymous directory. Nobody removes the profile from stranger discovery and matching. Existing connections and pending requests retain necessary profile access; blocking is the stronger per-person restriction. Relevant-only access requires a current evidence-backed match. Request audience is checked separately: a visible profile is not automatically requestable. Mutual connections exclude a blocked intermediary. These rules are server-enforced in profile, matching and request procedures/RLS.

Phone sharing is a separate opt-in. Even when Connections is selected, no phone field is added to profiles, matching results, review projections, conversation rosters or search. `profile_phone` reads only an Auth-confirmed phone after a fresh existing-connection/privacy/block check, or for the account owner. Unavailable, unshared or unknown targets return null. It permits 20 reveal attempts/hour and never returns a service credential or Auth row. Changing back to Nobody or blocking denies the next lookup immediately.

The phone is requested only when the viewer presses View shared phone number. It stays in component memory, outside Query and persistent storage, for at most 30 seconds. Leaving the profile/backgrounding clears it, and a generation check discards a late response after leaving. A previously viewed/copied number cannot be recalled. The 30-second display interval is a UI lifetime, not a revocable remote copy guarantee.

Profiles and Connect accept coarse city/neighborhood text. Mobile and interpreter validators reject common coordinates, building numbers, street-address terms/abbreviations and multiline input; the database CHECK enforces the profile boundary for all writes. Unicode place names are supported; mobile normalizes NFC. This is bounded text validation, not geocoding or proof that arbitrary user text cannot identify a place. Profile bio and review comments are user-authored, so users must avoid voluntarily including private details. Matching never collects device GPS. Explicit one-point location sharing remains inside an authorized conversation and is separate from discoverability.

The mobile/server source boundary remains intact: mobile does not import server modules. Validator parity tests cover supported English/Georgian examples, and authenticated integration exercises the database constraint. Trusted service writes have EXECUTE only on the pure area validator because CHECK constraints evaluate under the writing role; client writes remain denied.

Local verification: four actual Auth users test defaults, cross-user mutation denial, unsupported privacy values, absence of phone/GPS summary fields, relevant/mutual eligibility, blocked intermediaries, explicit phone consent/revocation/block and coarse input validation. Three component tests cover timeout, late-response discard and background clearing. Two real local OTP browser accounts saved/reopened settings, revealed the authorized development phone, restored Nobody and verified a new lookup returned unshared. No physical-device or cloud verification is claimed.
