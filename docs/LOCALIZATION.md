# Mnelo localization

English is the initial default; Me → Account switches to ქართული. Both resource dictionaries are complete and typed. Mnelo and its editable positioning remain centralized. Connect is translated as the action, not renamed to the brand. User-authored profiles, requests, messages and real device metadata are never translated automatically.

The en/ka preference persists before becoming visible, using SecureStore on native and only a two-character localStorage value in the browser QA adapter. Auth remains memory-only on web. Serialized writes and a restore revision guard prevent stale asynchronous reads from undoing the latest selection; storage failures retain the previous visible choice. Shared text/input accessibility language and the browser document language follow it.

Country labels and a small Gregorian month/number subset use pinned [Unicode CLDR 48.0.0 data](https://github.com/unicode-org/cldr-json/tree/48.0.0/cldr-json), with its [Unicode license](licenses/UNICODE-LICENSE.txt). The subset comes from cldr-localenames-full/main/{en,ka}/territories.json, cldr-dates-full/main/ka/ca-gregorian.json and cldr-numbers-full/main/ka/numbers.json. English country names also use the subset because the tested Android Hermes runtime lacks Intl.DisplayNames; ISO codes alone made name search unusable. This avoids silent English fallback on runtimes without Georgian ICU; it is not a general calendar/Intl polyfill. Actual timestamps use device-local time; requested calendar dates retain their exact day. Canonical interpreter vocabulary is translated for presentation only; unknown terms stay unchanged.

Migration 061 adds a checked device locale and returns it only to the service dispatcher. The worker generates generic localized copy without phone/name/message/location content. Migration 062 validates the device IANA zone and expires available-today at the next local midnight, including timezone/DST rules from PostgreSQL. Neither preference exposes exact location.

Native config declares en/ka and generates localized iOS permission descriptions plus Android locale resources. OS permission prompts follow OS/app language rules independently of the in-app switch. Final voice-over, native keyboard, Georgian glyph and largest-font checks require actual supported builds/devices. The copy needs owner/native-speaker editorial review before release.

Run npm run check (including resource parity, formatting, persistence/race and inline-source checks), npm run test:localization, test:notifications, test:profiles, db:test and check:edge. The integration test uses reserved local accounts and a captured HTTP push adapter, not live Expo delivery. Source guard covers explicit JSX text and UI labels; it supplements runtime inspection rather than proving every possible dynamic string is localized.
