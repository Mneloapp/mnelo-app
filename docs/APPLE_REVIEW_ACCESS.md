The owner authorized two separate reviewer accounts on September 12 after Apple required working sign-in details for external TestFlight review. They may contact each other; they must not reach the two real tester accounts. This is explicit, disclosed review access, not a change to normal SMS verification or a claim that sign-in is unnecessary.

## Enrollment

The two numbers are from the reserved fictional US range: +1 202 555 0198 and +1 202 555 0199. Each has a different random 128-bit access key, entered in a masked Review access key field, not the six-digit SMS field. The screen explicitly says no SMS is sent; Me labels the review account. Each signed registration attempt is bound to the device key and selected account, lasts ten minutes and allows at most five checks. The existing nonce/rate/concurrency guards remain. Normal enrollment only accepts six-digit provider OTPs, still requires one of the two real admitted numbers and retains persistent SMS budgets.

The server stores only SHA-256 hashes of the random access keys in an expiring, validated private configuration. They expire fourteen days after generation; no access key is embedded in the app, repo, command arguments or output. The owner's private instruction file is only for Apple's private sign-in/review fields. Existing pinned public keys cannot be silently replaced, including review accounts. If Apple needs another installation after enrolling, arrange a deliberate review-only reset; never reset the real cohort.

Mobile review access is limited to the exact preview identity service and the two reserved numbers. Local six-digit fixture accounts remain loopback-only and are rejected in hosted preview/production. The client flag is disclosure, not an authorization decision. Review keys are not saved in local enrollment receipts, vault backups or profile data.

## Server boundary

`IdentityAccess` derives membership from the registered phone's private index and server review configuration. No client-supplied cohort or role is accepted. The real admission list is unchanged; overlapping real/review configuration is rejected. Active bindings cannot switch between cohorts. Lookup returns no result across cohorts. Unregistered/expired/revoked identities cannot obtain relay admission or new TURN credentials. Relay probes hide cross-cohort presence and signed message/call offers are not forwarded across cohorts. Push dispatch checks the recipient owner's cohort even if a caller has a valid foreign wake capability. Expiry/revocation is evaluated on current requests, not a stale socket cache.

Hosted relay and identity now run together under an explicit operator configuration so the same current registry policy applies synchronously to every route, with no extra public identity API or copied phone database. The relay still has no message/media/history queue or recording. The normal phone registry schema is unchanged. Reviewer phone indexes/public keys and optional push routing use the existing minimal metadata tables. This is application authorization isolation on shared development infrastructure, not separate machines, a separate TURN network, or an independent protocol audit.

## Deployment and revocation

Generate credentials once with `node --import tsx scripts/configure-review-access.ts --create-owner-review-credentials`. It writes owner-only files under `~/.config/mnelo/apple-review/`, rejects existing files, and never prints their contents. `access.json` contains hashes; `private-instructions.json` contains the two review access keys and must never be deployed as mobile/server public content. Preserve these files; do not regenerate credentials that have already been given to Apple without an explicit rotation.

After full QA and a clean commit, build and hash-verify the hosting bundle. Install only the hashed `access.json` as `/etc/mnelo/review-access.json`, root-owned 0600; load it through systemd. Install `identity-routing.conf` and `identity-review.conf` into the identity service's drop-in directory. Stop/disable the old standalone relay service before starting the combined runtime, retaining its unit and old code for rollback. The identity service gains only TCP bind permission for loopback port 8084. Existing HTTPS/WSS URLs, Caddy, firewall, SMS configuration, index key, identity data and push keys are preserved.

To revoke review enrollment/routing, remove only the review drop-in and its private credential source, reload systemd and restart identity. Keep `identity-routing.conf` and the cohort-aware code so real-user signaling remains protected. Time expiry also denies further reviewer routing. Old local review history stays on each test device; expiry does not delete it. Remove only positively identified review registration/push metadata after the review period, preserving real identities, budgets and index keys. Do not claim metadata deletion until it is performed. No recurring automation or automatic data deletion was installed.
