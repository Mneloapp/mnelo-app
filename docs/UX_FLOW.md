# Mnelo messenger UX

> September 12 update: Me → Edit profile includes optional photo and business-card details; Share my card opens a real QR plus system share/copy. New contact offers Scan QR; validated invitations open a preview and explicit verification before Add. Chats/Calls avatars use locally received photos. Three tabs and originating-modal behavior remain. [Complete flow](PROFILE_CARDS_QR.md).

Navigation: **Chats | Calls | Me**. Calls replaces the removed Connect tab under the owner's updated instruction (2026-09-10). Calls also remain available inside a direct conversation.

Each primary screen uses its own localized title — Chats, Calls, Me — in the approved Inter Semibold / Noto Sans Georgian typography, with a shared header height. The Mnelo wordmark remains a distinct brand asset on Welcome. Tab switching preserves native layout and local screen state; it does not collapse and remeasure the outgoing page.

Chats → compose → **New chat** modal → search or select an alphabetically grouped local contact → conversation. New call uses the same compact search/list layout, with voice and video buttons directly beside each contact. Selecting a person dismisses the composer before opening the conversation/call. Back returns directly to the originating tab; closing a composer opened through Me → Contacts also returns to Me. Native iOS presentation supports sheet dismissal; nested screens retain back and close controls. Reduced motion is respected.

Calls → local voice/video history → contact actions → voice/video call or open conversation. Calls → plus → **New call** → contact's voice/video button. A live authenticated peer connection is required; unavailable calls show an explanation. An ongoing call can be reopened from this tab or its composer. History uses 40-entry cursor pages from the existing encrypted local database. Removing an entry affects Calls and its conversation on this device only. Existing records contain media type, end time and ended/failed outcome; the UI does not invent direction, missed-call classification or duration.

New call → **Keypad** → full international number → **Voice call**. The in-app keypad supports country-code prefix, digits, delete and hold-to-clear; entry stays stable while the number is incomplete. The explicit action looks up the number and starts voice for an already trusted, online contact without a second chooser. A newly found identity requires the existing full-key comparison and local contact naming before calling. An already pinned contact keeps the saved local name and key. Own, hidden, missing and blocked identities cannot start a call. Editing the number clears the previous result; blocking is checked again at the action boundary. Lookup requires the caller's own verified number and does not send SMS. These are internet calls to Mnelo users, not carrier/PSTN dialing. Without a connected number service the keypad remains usable and the call action disabled; no successful lookup/call is simulated.

Picker search filters saved names locally. Entering a complete international number offers an explicit chat/call-by-number action. Typing does not query the number registry or probe contact presence. New contact opens separate phone/code options; saving returns to the picker. My Mnelo code is a separate screen. Invite opens the OS share sheet only after the user's tap; no invitation is sent automatically.

The owner's September 11 navigation request follows WhatsApp's documented [new-contact path](https://faq.whatsapp.com/5472030609512325/?locale=en_US&cms_platform=iphone) and [new-call / keypad pattern](https://faq.whatsapp.com/1153602608602452/?cms_platform=android&locale=ml_IN). This is a functional interaction reference, not a claim of a pixel-for-pixel comparison against a current WhatsApp installation. Mnelo keeps its approved identity, local contact storage and explicit trust boundaries.

Launch: approved Mnelo mark during local initialization (minimum 700 ms after fonts load), then a centered large Mnelo wordmark > integrated country-code/number field + Continue > six-digit SMS verification > Chats. Welcome advances automatically; it has no network dependency, animation or extra button. Registration has no discovery checkbox or long introductory copy. Privacy information is available on demand in a dismissible modal. No name-first step. Typing or selecting a country never sends SMS automatically. Wrong/expired codes, resend cooldown and provider failures stay on registration. All feature routes and incoming call UI are gated until verification. A verified installation reopens offline; an existing unverified installation enrolls with its original keys/history intact. Before creating a new identity, Restore backup imports the user archive/key and then returns to number verification.

New chat / New call → New contact → Find by phone number → complete known number → result public code → compare with the person through a trusted channel → save local contact name → picker. Own number verification is required for lookup. No partial-number search, phone directory browsing, bulk address-book upload or silent replacement of saved keys. Both devices must add the corresponding peer. Phone number is the primary discovery identifier and discovery is enabled at registration. It can be disabled later in Me > Privacy; number changes preserve the previous choice. Hidden and unknown numbers have the same no-result response. Unlink removes only the registration mapping, not anyone's conversation copies.

New chat / New call → New contact → Add with Mnelo code → confirm identity through a trusted channel → save local name → picker. Both devices must trust the corresponding identity for a direct connection. Group owners may introduce member keys through authenticated group membership; this is delegated group trust, not a fabricated verification badge.

Chats support local pending/delivered/read state, text, photos, files, voice notes, explicit location/contact sharing, reply, reaction, forwarding and local deletion. History is local and paginated. Offline means waiting on the sending device. No platform queue is implied.

New chat → New group → name and select contacts → create → conversation. Group details let the owner change members/name. Other members can leave locally; owner notification is retried when connected. Existing history stays on each device.

Me shows a local @username and optional first/last names, editable without affecting keys or conversation history. A username is a display alias, not globally reserved/searchable. Me > Change phone number is the only phone-entry setting; verification must succeed before it replaces the old number. Privacy contains number discoverability/unlink; unlink locks entry while retaining local history. Account erasure optionally unlinks the number before deleting local data, and stops on service failure if unlink was requested. Backup export remains user-controlled; the app never equates a share sheet with confirmed cloud storage.

The approved warm-white, dark text and lime identity remain unchanged. Product copy is centralized and editable in English/Georgian. Call UI uses the existing dark appearance. There is no final security badge or reviewed-encryption promise.

## Chats search, filters and attention

Chats has an always-visible integrated search bar with a clear action; the header retains New message. Filters are All / Unread / Direct / Groups, horizontally scrollable at large text sizes. Search combines with the selected filter and does not query a phone/contact directory. Tabs show unread-message and unseen-missed-call counts independently (99+ visually; exact accessible count). Call history labels missed, declined, unanswered, failed and completed calls accurately. Me → Notifications exposes the opt-in local-alert permission and the closed-app delivery limitation.

## September 13 — physical feedback refinements

- Message reactions occupy a separate badge below the bubble; identical reactions show a count. They are never appended to the message body. Outgoing delivery leaves are compact at the lower trailing edge: absent while pending, outline after acknowledgement, lime after read. Timestamps remain revealed by horizontal swipe. Text selection no longer opens a second system Copy menu over message actions.
- Shared action sheets dismiss via backdrop tap, accessibility escape or Cancel. Chat options use icon rows. Clearing history opens a separate native confirmation; it only removes this device's copy. Full-screen country, privacy and photo pages retain explicit close controls.
- Calls show incoming/outgoing direction, compact date/time and media type. Missed calls remain red and explicitly labelled after the unread badge clears. Historical records without a direction remain unspecified. No Schedule/Favorites features were added.
- Native interface text uses iOS/Android system fonts and a tighter body line height; the approved Mnelo wordmark remains artwork. Web typography is unchanged.
- Photo viewing owns its modal safe-area provider, uses light status-bar content, keeps Close in the top toolbar, and offers one large Save or share photo action at the bottom. This opens the OS sharing sheet (including Save Image on iPhone), not an automatic gallery write. Native zoom remains handled by the existing iOS scroll view.
- With Contacts permission, the device address-book name takes precedence in existing contact lists, chat search/headers, replies, calls and contact cards. Matching uses complete normalized numbers and only locally pinned phone/key bindings. Names are a read-only in-memory projection: changing permissions, resuming the app or changing bindings refreshes it. It never overwrites a saved Mnelo alias, sends an automatic profile update, or uploads the address book. Denial/revocation restores the saved alias. iOS limited access is respected.
- Missing recipient Signal identity/prekeys shows a recipient-readiness explanation rather than a service-update error. Queued messages remain local and retry when the recipient updates/opens Mnelo; no fallback to the older protocol is introduced. Genuine service incompatibility remains a separate state.
