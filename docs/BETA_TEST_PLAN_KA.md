# Mnelo — ორი iPhone-ის სატესტო გეგმა

> Updated owner acceptance: background/closed-app message notifications and system incoming calls are mandatory before the two-phone beta is considered ready. Build 2 is preserved as evidence, not a completed candidate. Native remote push and CallKit implementation/physical acceptance are now required.

მიმდინარე მდგომარეობა, 12 სექტემბერი: Mnelo 0.1.0 (9), com.mnelo.messenger. Xcode-ში ორივე iPhone-ზე build 9-ის დაყენება დადასტურებულია. მეორე iPhone Air-ზე USB-ით დაყენებული დამოუკიდებელი Release ვერსია გაიხსნა და ნომრის შეყვანის ეკრანი რეალურად შემოწმდა. Apple-ის გარე TestFlight განხილვის დასრულება ამ ტესტის დასაწყებად საჭირო აღარ არის. მეორე ტელეფონის რეგისტრაცია მფლობელმა დაადასტურა; სერვერზეც ორივე ნომერი და მეორე iPhone-ის შეტყობინებისა და ზარის Sandbox არხები დაფიქსირდა. რეალური ორმხრივი კავშირი ჯერ შესამოწმებელია. ჩვეულებრივი რეგისტრაცია დაშვებულია მხოლოდ შეთანხმებულ ორ ნომერზე; Apple-ის შემმოწმებლები ცალკე, იზოლირებულ ჯგუფში არიან.

1. პირველ iPhone-ზე არსებული Mnelo არ წაშალოთ. განახლების შემდეგ Chats უნდა გაიხსნას ხელახალი SMS-ის გარეშე. მეორე iPhone-ზე პირველად შეიყვანეთ თავისი ნომერი და მიღებული კოდი. კოდები ჩატში არ გამოაგზავნოთ.
2. პირველადი კონტაქტის გაცვლისას ორივე აპი გახსენით. Me → Notifications-ში ჩართეთ შეტყობინებები და გადაამოწმეთ კავშირის სტატუსი. ორივე ტელეფონიდან დაამატეთ ერთმანეთი ნომრით; ორივე მხარეს უნდა ჰქონდეს მეორე მონაწილის კონტაქტი. სახელები შეგიძლიათ Me-ში შეავსოთ.
3. გაცვალეთ ორი მოკლე სატესტო შეტყობინება. შეამოწმეთ მიღება, პასუხი და წაკითხვის ნიშნები. შემდეგ სცადეთ ფოტო, პატარა ფაილი და ხმოვანი შეტყობინება.
4. ერთი iPhone დატოვეთ Wi-Fi-ზე, მეორეზე ჩართეთ მობილური ინტერნეტი. გაიმეორეთ ტექსტი, ხმოვანი ზარი და ვიდეოზარი. შეამოწმეთ პასუხი, უარყოფა, დადუმება, დინამიკი, კამერა და დასრულება.
5. დროებით გათიშეთ ინტერნეტი. შეტყობინება უნდა დარჩეს გამომგზავნის ტელეფონში მოლოდინის მდგომარეობით და კავშირის აღდგენისას გადაიგზავნოს დუბლირების გარეშე.
6. სატესტო კონტაქტი დაბლოკეთ და გადაამოწმეთ, რომ ახალი პირდაპირი კავშირი წყდება. ისტორიიდან ერთი სატესტო შეტყობინების ლოკალურად წაშლა მეორე ტელეფონის ასლს არ უნდა შლიდეს.
7. მიმღების აპი ფონზე გადაიყვანეთ, შემდეგ ეკრანი დაბლოკეთ და ცალ-ცალკე გამოსცადეთ შეტყობინება და ზარი. გაიმეორეთ აპის ცივი გაშვება, პასუხი, უარყოფა, უპასუხო ზარი და ვიდეოსთვის აპის გახსნა. ნებართვის უარყოფა და ქსელის დაკარგვაც შეამოწმეთ. ახალი სისტემური გზა კოდში დამატებულია, მაგრამ რეალურ მოწყობილობებზე მიღება ჯერ დასადასტურებელია. ორივე აპის ერთდროულად მიუწვდომლობისას შიგთავსი გამომგზავნის ტელეფონში რჩება; მიღებულად არ უნდა მოინიშნოს.

გამოიყენეთ არასენსიტიური სატესტო ტექსტები/ფაილები. ეს ფუნქციური ბეტაა და არა დამოუკიდებლად აუდიტირებული ან საჯარო გამოშვებისთვის დასრულებული პროდუქტი. ავტომატური Drive/iCloud სინქრონიზაცია არ არის ჩართული. არსებული აპის წაშლა ადგილობრივ ისტორიას წაშლის.

წინა TestFlight ეტაპის ისტორია: Apple-მა 0.1.0 (4) წარმატებით დაამუშავა; დაშიფვრის კითხვარიც შევსებულია მფლობელის დადასტურებული პასუხებით. პირველმა მფლობელმა დაადასტურა TestFlight-იდან დაყენებული აპის გახსნა და შეტყობინებებზე Allow. 12 სექტემბერს, 13:19:53-ზე სერვერზე დაფიქსირდა ამ iPhone-ის შეტყობინებისა და ზარის Production არხები. რეალური მიღება ჯერ შესამოწმებელია. მეორე ტესტერი დამატებულია Mnelo Preview ჯგუფში. Apple-ისთვის ორი ცალკე ანგარიში უკვე მომზადდა და სერვერზე შემოწმდა; ისინი თქვენს ანგარიშებს ვერ უკავშირდება. შემმოწმებლის კერძო შესვლის ინფორმაცია Apple-ში შენახულია. ვერსია 5 Apple-მა წარმატებით დაამუშავა და გარე შემოწმებაზეა — Waiting for Review. ავტომატური მოწვევა ჩართულია; Apple-ის დამტკიცების შემდეგ TestFlight-ით განახლებაც შესაძლებელი იქნება. მანამდე მეორე iPhone-ზე build 9 უკვე USB-ით დაყენდა.

USB ვერსიას ჩაშენებული პროგრამა აქვს და Mac-ის განვითარების სერვერი გაშვებული არ სჭირდება. მას Apple-ის Development შეტყობინებების არხი აქვს, TestFlight ვერსიას კი Production. ორივეს რეალური შეტყობინება და სისტემური ზარი ცალ-ცალკე უნდა შემოწმდეს.

Production APNs-ის გასაღები ჩართულია სერვერზე. Apple-მა build 3 უარყო ITMS-90683 შეცდომით — აკლდა NSMotionUsageDescription; build 4-ში შესწორება Apple-ის დამუშავებით დადასტურდა. არსებული პირველი iPhone-ის აპი არ წაშალოთ. Android-ზე იგივე ტესტები დამატებით მოიცავს Recents-იდან დახურვას, Force stop-ის ცალკე შეზღუდვასა და სისტემურ ზარის ნებართვებს. Firebase-ის Mnelo Development პროექტი შექმნილია, ანალიტიკა გამორთულია; Android კონფიგურაცია და სერვისული გასაღები ჯერ დასასრულებელია. Firebase მხოლოდ Android-ის შეტყობინების/ზარის სიგნალს ემსახურება, რეგისტრაციის SMS-ს კვლავ Infobip აგზავნის.
