**D: [GHSA-vcc3-ghjq-m6fr / CVE-2026-45822](https://github.com/advisories/GHSA-vcc3-ghjq-m6fr)** concerns excessive work on malformed percent-encoded input in decoder releases through 0.4.2; 0.5.0 fixes it. ## Native input mitigation and its limits

app/+native-intent.tsx uses Expo's [official native-intent hook](https://docs.expo.dev/router/advanced/native-intent/). V1 external links are launch-only: every external path becomes `/`, regardless of initial/warm state. The hook does not decode, parse, log or forward the untrusted input. Internal typed navigation and server-authorized push actions retain their existing behavior. This deliberately does not implement arbitrary external conversation/profile links or production universal links.

Installed Router 57.0.20 source confirms cold getInitialURL (sync and promise) and warm subscribe invoke the hook before navigation query decoding. Five regression cases execute those actual installed routing functions with controlled OS event adapters, including iOS/Android paths and oversized/malformed/private-route input. An actual 6,178-byte malformed warm Android intent returned to Chats and the next tab interaction succeeded. A cold custom-scheme test reached the Expo Development Client launcher; it did **not** execute application JavaScript, so it is not an application cold-launch PASS. Phase 30 subsequently passed actual standalone Android cold and warm launches with a 6,153-byte malformed native URI: the embedded app rendered Welcome, the next Continue interaction opened Phone, and the warm process survived. No Metro tunnel was present. On September 9, the Xcode 26.6 standalone iOS Simulator build also passed actual cold/warm 6,153-byte malformed inputs with Metro confirmed stopped: Chats rendered, the warm process survived and subsequent Me/Connect interactions worked. See [native evidence](audits/ios-26.6/native-result.json). No web mitigation is claimed: this repo enables browser rendering only for an explicit local development preview, and must not publish that messenger preview as a production website.

The mitigation reduces the known native entry exposure but does not remove the installed advisory or certify every future route/provider. Controlled internal testing is supported by the installed-router regressions and dated Android/iOS standalone checks. Retain the three entries on the release risk register: a compatible upstream fix remains preferred, and every final distribution binary must repeat the cold/warm regression. Physical and hosted release acceptance remain open; no arbitrary URL parsing is authorized by these results. Do not add legacy_subscribe, external path forwarding or new unvalidated router entry adapters without revisiting this audit.

## Evidence and interpretation

The audit uses the installed packages, package-lock.json, `npm audit --json`, `npm audit fix --dry-run --json`, installed call sites, and iOS/Android release-bundle source maps. The dry run proposed **0 added, 0 removed, 0 changed packages**. A generic `fixAvailable: true` on one inherited entry did not translate into an available non-breaking fix.

All 14 packages have npm production dependency paths. That flag means they are installed with Expo; it does **not** establish that their vulnerable code is shipped or runs on a phone. Below, “build” describes execution context, not merely the package.json devDependency flag. Three entries are direct dependencies; the others are transitive. The two root advisories propagate through ancestors, so the rows must not be counted as 14 independent vulnerabilities.

**U — UUID bounds checking:** [GHSA-w5hq-g745-h8pq / CVE-2026-41907](https://github.com/advisories/GHSA-w5hq-g745-h8pq). Affected `uuid` versions include <11.1.1; the affected API methods are v3/v5/v6 with a supplied output buffer. Patched releases include 11.1.1, 12.0.1 and 13.0.1. The installed Xcode parser invokes `uuid.v4()` without an output buffer at `node_modules/xcode/lib/pbxProject.js:90`. The vulnerable `node_modules/uuid` package and `node_modules/xcode` are absent from both exported mobile source maps. Expo's differently implemented internal UUID module is present and is not this advisory's package.

**D — Malformed URI decoding:** [GHSA-vcc3-ghjq-m6fr / CVE-2026-45822](https://github.com/advisories/GHSA-vcc3-ghjq-m6fr). Affected decoder releases are ≤0.4.2; fixed in 0.5.0. Both mobile source maps contain `query-string/index.js` and `decode-uri-component/index.js`. Router's installed `build/react-navigation/core/getStateFromPath.js:499` calls `queryString.parse(query)`, which defaults to decoding and calls this decoder. External URLs are part of the `mnelo` scheme surface; absence of product features does not remove this parser exposure.

A bounded local probe of the **installed query parser**, in a separate Node process, completed an ordinary 18-byte query in 26 ms. A 6,146-byte synthetic malformed query exceeded 1,500 ms and was killed by the harness. This confirms a slow input family in the dependency; it is not a successfully demonstrated attack on a running iPhone app. Native exploitation was not tested because the app could not compile. Treat the shipped parser exposure as a runtime availability risk.
