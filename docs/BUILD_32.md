# Build 32: call setup under load and member-first groups

Answering a call could remain on Connecting while bulk uploads or pending network requests occupied the device queue. Urgent call controls now preempt between bulk uploads, retain their priority at the shared HTTP scheduler, and incoming delivery hints interrupt the normal batch for an urgent inbox fetch. Requests remain serial and paced at 750 ms, with the existing rate-limit backoff and fairness for ordinary traffic. Durable Signal ciphertext and retry state are preserved.

The first relay candidate may fail on the current network while a usable fallback arrives before ICE gathering completes. New candidates now trigger a signed description update after a short batching interval instead of waiting for gathering completion or its ten-second deadline. Updates still validate the call, fingerprint, ICE credentials and media sections. Incoming/outgoing direct calls prefetch cached expiring relay credentials while ringing, without capturing the recipient microphone before acceptance. The connected state and timer still require the media connection.

Group creation now first presents searchable members and selection chips, then a second page for the group name, optional photo and description. Additional profile fields expand below. Going back preserves selected members and the draft; photo preparation and invalid fields disable creation. Saved contact names take precedence when phone contacts resolve to an existing identity, and blocked/self/changed phone bindings are excluded. The existing limit is 15 other members.

Group details use an additive local migration and an independently encrypted, durable owner-authored control. Membership snapshots retain their older schema, so previous clients can still join; they need this update to display the new details. Early metadata waits for its membership revision, stale updates cannot overwrite newer details, and a non-owner cannot change the group profile. Details and photos survive restart and backup restore. The owner can edit them later; group avatars appear in Chats and the conversation header.

## Validation

Full checks passed 647 tests: 486 Jest tests across 93 suites, 3 server tests and 158 device/protocol tests, plus TypeScript, lint, formatting, security, environment, localization and brand checks. A subsequent focused protocol run also passed after extending the group test to cover photo backup/restore. Queue tests use actual Signal encryption and prove call preemption during an already-started bulk batch, prompt fetching after a remote hint, and unchanged serialization/rate budgets. The ICE regression fixture adds fallback candidates while gathering remains incomplete. Component tests cover member-first navigation, Georgian search, back preservation, photo preparation, invalid fields and retry after failed creation.

An isolated browser harness using actual relay-only TURN/WebRTC and synthetic media passed voice/video, bidirectional RTP, mute, hangup, decline and capture-denial cleanup. Answer-to-RTP measured 1,336/1,243 ms for voice/video with UDP/TCP available and 1,315/1,162 ms with TCP-only TURN. These are single local measurements using an in-memory signaling queue: they do not establish native iPhone, production Signal/HTTP, APNs or CallKit latency. A Georgian browser component fixture verified both group pages and additional fields without console errors; native navigation and keyboard behavior still need phone acceptance.

The existing server runtime is unchanged. Signed archive, public-source CI and TestFlight availability are recorded in BUILD_LOG when completed. Final acceptance requires both phones updated to build 32 and a new call after answering, particularly on the network that previously took 10–15 seconds.
