# Mnelo blocking and reporting

Blocking is an authenticated database operation, serialized per pair. It prevents mutual discovery/profile access, new requests and direct conversation access/sends. Pending requests are cancelled; stored ringing/accepted call sessions are ended. External LiveKit disconnection must be integrated and verified in Phase 15; a database transition is not proof that a live room disconnected. Private shared-group policy conservatively restricts both affected users while they share membership, while preserving their ability to leave. There is no public presence feature or client presence-write policy.

Me → Privacy → Blocked people provides 20-row cursor pages with only the current user's blocked identities. The narrow projection includes current name/username so the user can undo a block; it does not reopen full profiles, avatars, phones or matching data. Unblocking removes only the caller's own block and restores access permitted by existing relationships/current privacy. It does not resurrect cancelled requests, create a connection or undo another person's block.

Block changes create/update `user_access_state` for each affected account, in consistent UUID order. Its own-account-only RLS/private Realtime payload is just ID, owner ID, revision and timestamp, without blocker/reporter identity or content. The app resets cached queries on this event so an open profile/chat does not keep rendering a stale authorized result. Previously viewed/copied/downloaded data cannot be recalled. No DELETE subscription is used by the app.

Reports support spam, scam/fraud, harassment, fake profile, unsafe behavior and other. Other requires a short explanation. A report is allowed for an accessible profile, own blocked profile, existing request counterpart or relevant current group participant. A referenced message must actually be readable by the reporter and authored by the reported person. Message references, not private body text, go in navigation parameters. The report screen also permits blocking, including a group participant whose full profile is not discoverable; sending a report is not a prerequisite for that action.

`submit_report` derives the reporter from Auth, validates reason/detail/context and uses a stable client UUID with exact-payload idempotency. It limits accepted reports to 5/hour and 20/day. The reporter can read only their own receipt/status, never alter moderation state. The subject and unrelated clients cannot enumerate reports or reporter identity. Server-only `resolve_report` transitions reviewing/resolved/dismissed and writes a private moderation audit record with a trusted operator reference. A client-provided admin string grants no authority. No admin dashboard, operator account or staffed production moderation service is configured; Report received means stored, not investigated or resolved.

Ordinary profile/message data is not copied into a public moderation record. Final evidence retention, account deletion and operational response policies remain Phase 17/18/release work; no response-time promise is made. Published eligible reviews remain subject to server-owned visibility status, independent of unilateral blocking.

Routes are explicitly guarded by an authenticated profile, including group, connection, completed-history, reviews and blocked-person screens. A route-inventory test catches Expo Router's automatic addition of unlisted feature files. Backend RLS/RPCs remain authoritative even if navigation is bypassed.

Local verification: four actual Auth users exercise private report/subject boundaries, message attribution, spoofed admin denial, service-only status change, idempotency/rate limits, actual generic access events, blocked discovery/message/request access and deliberate unblock. Privacy and private-group regressions plus 52 pgTAP tests pass. Two local OTP browsers exercised message reporting, block confirmation, automatic clearing of the peer's open profile, blocked-list management and restoration after unblock. Anonymous direct feature routes displayed the welcome gate. Vertical report choices were inspected at 390×844 after a wrapping issue was found. Native/device/real-call enforcement remains unverified.
